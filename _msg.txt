Say when a run will end; delete the stock check's own chat traffic

An overnight run stopped three minutes after it started. Not a crash - the
config had run_minutes=3 and max_refills=3, so the automation did exactly
what it was told and then turned itself off. Nothing ever said it would.

"run_minutes 3" reads naturally as "check every 3 minutes". It actually
means "stop after 3 minutes", and the same ambiguity applies to max_refills.
That is a UI failure, not a user error:

  - Setting either now replies with what it really does ("shuru hoar 3 min
    por task NIJEI BONDHO hobe") and how to undo it. delete_when_done warns
    that the numbers will be removed from the bot.
  - Start states the finish conditions up front, including the common case:
    with no limits it says so explicitly, so "it will keep running" is
    confirmed rather than assumed.
  - The web panel shows the same warning next to the fields, updating as you
    type.

A run ending on its own is correct behaviour; a run ending silently is
indistinguishable from a crash, which is what made this feel broken.

Tidy the stock check
  /st and its reply are bookkeeping, and on a 2-minute interval they bury
  the chat. Both sides of the exchange are now deleted after the reply has
  been read and parsed - the data is in hand before anything is removed.

  Added delete_messages to the userbot (Telethon and Pyrogram). Tidying is
  cosmetic, so it can never cost a cycle: a backend without delete support,
  a message too old to delete, or an outright API failure all leave the run
  untouched. Controlled by tidy_stock_messages (default on).

726 passing, smoke 10/10.
