OTP bot gets its own chat thread - no more "which chat do I send it to?"

Files and trigger words were previously global: a number file dropped into
any conversation joined the queue, and a plain "start" anywhere fired the
automation. That made two things ambiguous at once - where the owner is
supposed to send files, and whether an ordinary word like "start" meant
anything special.

There is now one dedicated thread that IS the OTP-bot workspace, created on
demand by /otpchat (Telegram) or the "Open the OTP Bot chat" button in the
dashboard's OTP Bot panel, and remembered in the automation's own config so
it is reused rather than recreated. Inside it: every uploaded file queues
automatically and start/stop/tag answers are intercepted deterministically.
Outside it: an upload is just an attachment for the next instruction and
"start" is just a word, exactly as before this feature existed.

The thread seeds itself with a titled first message so it is recognisable
in /history and the dashboard's thread sidebar instead of appearing as a
nameless "New chat", and the dashboard shows which thread you are currently
in so the answer to "where do the files go" is visible rather than
remembered. The upload API now reports queued_for_otpbot so a caller can
tell the two cases apart.

Fixed along the way: ensure_thread called reset_session on a chat that may
have no chat_sessions row yet - reset_session is an UPDATE, so it silently
matched zero rows and left the chat on its default thread.

595 tests (was 591: 3 for thread creation/binding/reuse and cross-thread
isolation, 1 that triggers stay inert outside the thread, plus API
auth/lifecycle coverage for the new endpoint), smoke 10/10.
