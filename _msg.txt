Web chat: file attach (paperclip), no attachments-only channel

The owner pointed out the web dashboard's chat panel had no way to send a
file - the only upload path was still Telegram's document handler.

New: POST /api/chat/upload, GET/DELETE /api/chat/pending_upload

Saves into uploads/ and writes pending_upload onto the owner's chat session
context - the exact same mechanism Telegram's F.document handler
(app/telegram/bot.py) already uses, same size limit, same filename
collision handling. Because both paths write to the identical session
field, a file uploaded from the web dashboard auto-attaches to the next
instruction whether that instruction comes from the web chat panel or from
Telegram - one shared pending-upload slot, not two competing ones.

Frontend: a paperclip button next to the chat input opens a native file
picker, uploads via multipart/form-data (still credentials: 'include', no
token ever touches the browser), shows the attached filename as a pill
above the input with a Remove button, and clears automatically once the
next message is sent (mirroring the reply the owner already gets on
Telegram: "I will attach this file automatically to your next
instruction").

Needs python-multipart for FastAPI's UploadFile - added to requirements.txt.

563 tests (5 new), smoke 10/10.
