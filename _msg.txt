Telegram buttons for the OTP panel; removals; web UI auto-refresh

Three gaps the owner hit in a row, all the same shape: the automation knew
things the owner had no way to change without typing exact phrases.

Removing work that should not run
  Files could only be dropped from the web queue list. There was no way to
  drop one from Telegram at all, and no way to drop an ALREADY-STARTED file
  from anywhere - the only lever was "stop", which halts everything.

  - remove_active_file() takes one file out of future refill cycles. It does
    not un-add numbers the target bot already holds; emptying the active set
    also flips enabled off, since nothing remains to monitor.
  - remove_by_country() drops queued and active entries together. Country is
    the unit the owner thinks in ("Bangladesh bad dao"), and after splitting
    one country can span several entries from different uploads, so matching
    by country avoids leaving stragglers.
  - clear_queue() empties what has not started, deliberately leaving running
    work alone.
  - Chat triggers: "<country> bad dao" / "remove <country>", "skip" at the
    tag prompt, "sob bad dao". country_to_remove() returns None for ordinary
    sentences, so mentioning a country never deletes it.
  - DELETE /api/otpbot/queue, /active/{id}, /country/{name}.

  Removing an entry now also clears a tag prompt pointing at it. A dangling
  prompt wedges the conversation: every later message is read as a tag answer
  for an entry that no longer resolves.

Buttons instead of remembered phrases
  New app/telegram/otp_panel.py: service picker (6 common services + "bad
  dao"), interval picker, cleanup-mode picker, and a control panel with
  start/stop, check-now, clear-queue and status. Callback data is
  "otp:<action>:<arg>"; a test asserts every payload fits Telegram's 64-byte
  limit, which is enforced at send time and otherwise only shows up as a
  button that silently does nothing.

  Handlers re-read state instead of trusting the keyboard they came from -
  the owner can tap a button on an hour-old message.

  set_cleanup_mode() exposes "tidy up" vs "wipe country first" as one choice
  because the flags underneath must move together; letting them drift gives
  you force-delete "enabled" but inert. Choosing wipe without a configured
  uid now says so rather than silently falling back.

Web UI auto-refresh
  The OTP panel changes on its own - the scheduler refills on a timer, and
  Telegram buttons write the same state - so an open tab went stale and
  misled. Polls every 10s while that panel is visible, pausing when the tab
  is hidden. Quiet mode skips the "Loading..." flash and holds off entirely
  while an input in the panel has focus, so a refresh never eats typing.

626 passing.
