Stop paying for dead providers; answer the common questions instantly

Measured first, rather than guessing at "the bot is slow":

  app itself      0.5ms   (not the problem)
  API over CF     0.7s    (network hop)
  omniroute       16s     to return 429 - every free model rate-limited
  ollama 7b       2.6s    warm
  ollama 1.5b     64s cold / 1.4s warm

So a reply cost ~16s of guaranteed failure before a working provider was
even tried, and the local model was usually cold because ollama's default
keep_alive (5m) expires during ordinary gaps in a conversation.

Failure cooldowns in the LLM manager
  A provider that just failed is skipped for a while instead of being
  retried on every single message: 120s normally, 300s for a rate limit
  (429s state their own window). Success clears it immediately. If every
  provider is cooling down the request is still attempted rather than
  refused - a cooldown is a latency optimisation, not a ban.
  Mutation-verified: removing the skip makes the test fail.

Keep the local model resident
  keep_alive is now sent explicitly (2h). The 18-64s reload was most of
  what "slow" actually meant on a CPU-only host.

Don't spawn a task pipeline when the router is down
  The fallback was a blanket TASK, so while providers were rate-limited
  even a plain question started a whole job. A direct question is now
  answered in chat: cheap and reversible, where a wrongly-spawned task is
  neither. Everything else still defaults to TASK so real work is never
  dropped.

Instant status and help in the OTP thread
  "status", "ki obostha", "stock koto", "help" and friends are answered
  from state with no model at all - these are the most common messages in
  that thread and they were waiting on a rate-limited provider for
  information already in hand. Matching is exact-phrase only, so
  "status report banao ekta file theke" is still a task.

Interface
  - Telegram: the typing indicator now refreshes every 4s (Telegram clears
    it after ~5s, so a long turn looked frozen), and there is a global
    "Off at" time picker - previously a stop time could only be set one
    country at a time.
  - stop_at is now a real global default that each country inherits and can
    override; the web UI gets the same field, plus a provider-health line
    that names a cooling-down provider instead of leaving "slow" unexplained.
  - The config endpoint uses exclude_unset, so clearing a stop time (empty
    string) is no longer silently dropped by the None-filter, and a stop
    time posted from the browser is validated like any other.

One existing test correctly pinned the old router behaviour for an
imperative sentence; my first heuristic was too broad and it caught it.
Narrowed to questions only.

762 passing, smoke 10/10.
