Split uploads by country; per-country service memory; /frcd support

A single uploaded file routinely holds several countries - one of the
owner's own exports mixes Dominican Republic area codes (1809/1829/1849)
with Bangladesh numbers - and the target bot keeps stock per country. Adding
such a file whole filed every number under one country's tag, and asking
"what tag for this file?" was the wrong question: the answer differs per
country inside it.

Uploads are now parsed before anything is queued. app/automation/
phone_countries.py resolves each number's country by longest-matching E.164
dialing prefix (longest-first specifically so +1809 stays Dominican Republic
instead of collapsing into +1 United States, and the NANP carve-outs for
Canada/Jamaica/Bahamas survive). Each country becomes its own queue entry
with its own split-out file containing only that country's numbers, so the
file the bot receives always matches the command that describes it. An
unrecognised prefix is reported as "+998"-style rather than guessed, so a
missing table entry is visible instead of silently mis-filed.

Service/tag is now remembered PER COUNTRY, and deliberately does not fall
back to the global last-used tag when the country is known - inheriting
Nigeria's answer for a Bangladesh file would quietly sell the numbers as the
wrong service, which is worse than one short question. The question itself
now names the country and how many numbers it found, so the owner can see
what they are answering about.

Adds /frcd (Owner: force-delete user numbers by country) as an optional
pre-add step. /useddelete only clears used/expired numbers, so re-adding a
country whose stock is still live just piles up duplicates - the bot reports
them as "dup". Off by default and inert without a configured uid; the web UI
exposes the toggle, the command template and the uid, and explains the
distinction.

Found while writing the tests: the per-country lookup fell through to the
global tag when a country had no entry yet, which reintroduced the exact
leak the split was meant to prevent. The test named it, so it is fixed and
pinned rather than shipped.

611 tests (was 603): country resolution incl. the NANP traps, mixed-file
splitting, split-file contents, single-country files left uncopied,
per-country tag memory, the country-aware question, {country} in the add
template, and /frcd firing per country before the add (and staying silent
when unconfigured).
